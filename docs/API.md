# API changes (ours)

Every new or changed endpoint: method, path, permission, request, response, errors. Follow Plane's existing API docs style.

| Method           | Path                                                                                                                                                                                                                                            | Permission                                                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST             | /api/workspaces/{slug}/projects/                                                                                                                                                                                                                | Workspace admin/member                                              | Accepts `target_date` (YYYY-MM-DD, nullable). `prd_page` is rejected on create (400).                                                                                                                                                                                                                                                                                                                                             |
| PATCH            | /api/workspaces/{slug}/projects/{pk}/                                                                                                                                                                                                           | Workspace admin or project admin                                    | Accepts `target_date` and `prd_page` (must be a public, non-archived page linked to this project; `null` clears). Invalid values give 400 `{"prd_page": ...}` / `{"target_date": ...}`.                                                                                                                                                                                                                                           |
| GET              | /api/workspaces/{slug}/projects/ and /api/workspaces/{slug}/projects/{pk}/                                                                                                                                                                      | Workspace admin/member/guest                                        | List and retrieve return `target_date` and `prd_page` (page id or null).                                                                                                                                                                                                                                                                                                                                                          |
| POST             | /api/v1/workspaces/{slug}/projects/                                                                                                                                                                                                             | API key, workspace admin/member                                     | Accepts `target_date`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| PATCH            | /api/v1/workspaces/{slug}/projects/{pk}/                                                                                                                                                                                                        | API key, project admin (or workspace admin who is a project member) | Accepts `target_date` and `prd_page` (same rules as the web-app PATCH; 400 `{"prd_page": [...]}` on an invalid page).                                                                                                                                                                                                                                                                                                             |
| POST, PATCH      | /api/workspaces/{slug}/projects/{project_id}/issues/ and .../issues/{pk}/ (also draft work items)                                                                                                                                               | Project admin/member (unchanged)                                    | Subtask rules (one level, due dates). 400 body: `{"parent_id" or "target_date": [msg], "error_code": [CODE]}` (DRF wraps each value in a list). Codes: `SUBTASK_SELF_PARENT`, `SUBTASK_PARENT_IS_SUBTASK`, `SUBTASK_HAS_CHILDREN`, `SUBTASK_DATE_AFTER_PARENT` (+ `parent_target_date`), `PARENT_DATE_BEFORE_SUBTASKS` (+ `subtask_identifiers` e.g. `["PROJ-12"]`, `latest_subtask_target_date`). Null dates are always allowed. |
| POST, PATCH, PUT | /api/v1/workspaces/{slug}/projects/{project_id}/work-items/ and .../work-items/{pk}/                                                                                                                                                            | API key, project admin/member (unchanged)                           | Same rules and codes as above; the parent field is `parent`, so errors are keyed `parent` or `target_date`. (PUT upsert exists in code but is not routed upstream.)                                                                                                                                                                                                                                                               |
| POST             | /api/workspaces/{slug}/projects/{project_id}/issues/{issue_id}/sub-issues/                                                                                                                                                                      | Project admin/member (unchanged)                                    | All or nothing: if any `sub_issue_ids` item breaks a rule, nothing changes and the response is 400 `{"error", "error_code", "issue_ids"}` (codes `SUBTASK_PARENT_IS_SUBTASK`, `SUBTASK_SELF_PARENT`, `SUBTASK_HAS_CHILDREN`, `SUBTASK_DATE_AFTER_PARENT`).                                                                                                                                                                        |
| POST             | /api/workspaces/{slug}/projects/{project_id}/issue-dates/ (Gantt)                                                                                                                                                                               | Project admin/member (unchanged)                                    | Every row is checked before any update or activity, using the batch's own dates (moving parent and subtasks together is allowed). 400 `{"error", "error_code", "issue_ids": [row id]}` with `SUBTASK_DATE_AFTER_PARENT` or `PARENT_DATE_BEFORE_SUBTASKS`.                                                                                                                                                                         |
| GET              | /api/workspaces/{slug}/projects/{project_id}/issues/, .../issues/list/, .../v2/issues/, .../cycles/{id}/cycle-issues/, .../modules/{id}/issues/, .../archived-issues/, /api/workspaces/{slug}/user-issues/{user_id}/; POST .../issues/ response | Unchanged                                                           | Each issue also returns `completed_sub_issues_count`: live subtasks in the `completed` state group (cancelled not counted). One subquery, no N+1.                                                                                                                                                                                                                                                                                 |
| GET              | /api/workspaces/{slug}/projects/{project_id}/search-issues/                                                                                                                                                                                     | Unchanged                                                           | `parent=true&issue_id=X`: only top-level issues, excluding X and its children. `sub_issue=true&issue_id=X`: only issues with no parent and no children; empty if X is itself a subtask; unknown or invalid X no longer crashes.                                                                                                                                                                                                   |
| (background)     | Parent auto-done (`bgtasks/subtask_rollup_task.py`)                                                                                                                                                                                             | —                                                                   | When a subtask's state changes and every live subtask is completed or cancelled with at least one completed, the parent moves to the project's first `completed` state. Logged as a `state` activity on the parent by the user who closed the last subtask (notification sent). Reopening changes nothing back.                                                                                                                   |
