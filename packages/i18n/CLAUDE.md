# i18n (`@plane/i18n`)

## Purpose

i18next (ICU message format) setup, React provider/hook, and all UI strings for the frontend apps. Index: `../CLAUDE.md`.

## Key files

- `src/locales/<lang>/<namespace>.json` — strings; 22 languages x 28 namespaces. **`en` is the source of truth.** (`locales/` at the package root is a symlink to `src/locales`.)
- `src/constants/namespaces.ts` — `NAMESPACES` list + `DEFAULT_NAMESPACE` (`common`)
- `src/constants/language.ts` — `SUPPORTED_LANGUAGES`, `FALLBACK_LANGUAGE` (`en`), `LANGUAGE_STORAGE_KEY`
- `src/core/instance.ts` — i18next instance; lazy-loads JSON per language/namespace, preloads all namespaces
- `src/hooks/use-translation.ts` — `useTranslation()` -> `t`, `currentLocale`, `changeLanguage`, `languages`
- `src/provider/` — `TranslationProvider`
- `src/types/keys.generated.ts` — `TTranslationKeys`, generated (git-ignored) by `scripts/generate-types.ts`
- `scripts/sync-check.ts` — finds missing/stale keys, cross-namespace collisions, leaf/prefix conflicts

## Rules for this folder

- Add/change English keys in `src/locales/en/<namespace>.json` first; **every locale must have the same keys**.
- Use the `translate` skill (`.claude/skills/translate`, `/translate`) whenever you touch locale files; it covers terminology, plurals and placeholders.
- A key must be unique across all namespaces of a language (all namespaces are searched via `fallbackNS`), and a key can't be both a string and a parent object.
- Keep ICU placeholders (`{count}`, `<tag>`) identical in every language.
- New namespace: add `<ns>.json` to **every** language folder and add the name to `NAMESPACES`.
- New language: add a folder copied from `en/`, then add it to `SUPPORTED_LANGUAGES` and `TLanguage` (`src/types/language.ts`).
- Never hand-edit `keys.generated.ts`; it is regenerated by `build` / `check:types`.
- CRM wording (Task, Sprint, Phase...) must stay consistent with the "Our words vs Plane's words" table in the root `CLAUDE.md`.

## Depends on / used by

- Uses: `i18next`, `i18next-icu`, `i18next-resources-to-backend`, `react-i18next`.
- Used by: `apps/web`, `apps/space`, `apps/admin`, `packages/blocks`.

## How to test

- `pnpm --filter=@plane/i18n sync:check` (report). CI runs `sync-check.ts --ci` (exit 1 on drift) via `.github/workflows/i18n-sync-check.yml`; locally `pnpm --filter=@plane/i18n check:sync` does the same.
- `pnpm turbo run check --filter=@plane/i18n`
